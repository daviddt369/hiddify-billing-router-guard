# Ноды выхода: поднять новую или перепривязать старую

Схема: пользователь заходит на **входную ноду** (RU, панель «Чебурнатор»), а наружу выходит через **выходную ноду** (DE, NL...: её IP видят сайты). Выход - обычная панель Hiddify (`install.sh --node`) плюс WireGuard-туннель до входной ноды. Один выход может быть подключён к входной ноде несколькими способами (VLESS из его подписки, WireGuard); входная нода выбирает самый быстрый (AUTO) или нужную страну.

## 1. Новый выход одной командой

На чистой Ubuntu 24.04 выходной ноды:

```bash
git clone https://github.com/daviddt369/hiddify-billing-router-guard.git && cd hiddify-billing-router-guard && sudo bash install.sh --node
```

Ставится чистый Hiddify без биллинга и маршрутизации (они нужны только на входной ноде). В конце печатаются ссылки админки этой ноды.

## 2. Подключить выход к входной ноде по WireGuard

Порядок важен: сначала ключ входной ноды, потом выход, потом подключение. Имя `de2` ниже - любое ваше название (маленькие латинские буквы, цифры, `-`).

1. **На входной ноде**: создать её ключ для этого выхода и получить публичный.

   ```bash
   bash node/ru-attach-wg.sh keygen de2
   ```

   Напечатает `PEER_PUBLIC_KEY=...` (публичный, его можно пересылать).

2. **На выходной ноде**: сначала проверка (ничего не меняет), потом применение. Для каждого выхода свой интерфейс, порт и подсеть туннеля (`10.66.70.x` у одного, `10.66.71.x` у следующего и т. д.).

   ```bash
   bash node/wg-exit.sh --check --if wg-de2 --port 51825 --srv-addr 10.66.71.1/30 --peer-tun 10.66.71.2/32 --peer-pub КЛЮЧ_ИЗ_ШАГА_1
   bash node/wg-exit.sh --apply --if wg-de2 --port 51825 --srv-addr 10.66.71.1/30 --peer-tun 10.66.71.2/32 --peer-pub КЛЮЧ_ИЗ_ШАГА_1
   ```

   В конце скрипт сам проверяет себя и печатает `SERVER_PUBLIC_KEY=...` и `ENDPOINT=IP:порт`. Если у хостера есть облачный брандмауэр (в его кабинете), откройте в нём этот UDP-порт.

3. **На входной ноде**: подключить (бэкап, одно «Применить», при сбое база возвращается).

   ```bash
   bash node/ru-attach-wg.sh attach de2 --server-pub SERVER_PUBLIC_KEY --endpoint ENDPOINT --tunnel-addr 10.66.71.2/32 --slot 1 --title Germany --iso DE
   ```

   `--slot` - номер страны на странице «Маршрутизация → Страны / локации» (без него выход попадёт только в общий пул AUTO). На новой панели есть 4 свободных слота (1-4). Первый выход нового узла строит конфиг роутера с нуля (скрипт сам делает два прохода), последующие добавляются одним «Применить».

   Если скрипт ответил, что собранный конфиг **удержан и ждёт решения** (код 4), значит в нём есть отличия, не объяснимые вашей правкой: откройте панель, «Маршрутизация», посмотрите отличия и нажмите «Применить новый конфиг» или «Не применять». База при этом не откатывается, роутер не тронут.

   Состояние туннеля: `bash node/ru-attach-wg.sh status de2` на входе (панель, работает ли роутер, счётчики устройства) и `bash node/wg-exit.sh --status --if wg-de2` на выходе: **рукопожатие смотрится здесь**, оно должно быть свежим, трафик растёт.

## 3. Подключить выход по VLESS (без WireGuard)

В админке выхода создайте пользователя и скопируйте ссылку нужного протокола из его подписки. На входной ноде: «Маршрутизация → Upstreams → добавить», вставьте ссылку; затем во вкладке «Страны / локации» отнесите узел к стране и нажмите «Применить».

## 4. Перепривязать выход к другой входной ноде (или входную ноду пересобрали)

- Входную ноду **восстановили из снимка** (`install.sh --restore`): узлы, страны и ключи WireGuard вернулись вместе с данными, ничего делать не нужно. WireGuard-пир на выходе **не привязан к IP входной ноды** (в его конфиге нет `Endpoint`), поэтому смена IP входа ничего не ломает. Проверьте только, что у хостера и в брандмауэре выхода нет фильтра по старому IP входной ноды.
- Входная нода **новая и без данных**: повторите шаги 1-3 для каждого выхода. `wg-exit.sh --apply` повторяемый: старый конфиг сохраняется рядом, пир заменяется на новый ключ.

## 5. Снять выход

На входной ноде удалить узел в панели («Upstreams») и нажать «Применить». На выходе: `bash node/wg-exit.sh --remove --if wg-de2` (конфиг и ключи переезжают в `/root/wg-wg-de2-removed-...`, не удаляются).

Правила брандмауэра на выходе пишет `wg-exit.sh` (в `PostUp` / `PostDown` конфига WireGuard), чужие правила он не трогает. Перед первым запуском на боевом выходе прогоните `--check` и прочитайте, что он собирается добавить.
