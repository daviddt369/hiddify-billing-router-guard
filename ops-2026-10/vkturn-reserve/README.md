Важное для проекта:
- Внутри хоста уже есть всё, что нужно для IP-трафика нового туннеля: любой пакет, отданный в SOCKS-inbound xray-router, идёт по тем же правилам, что основной вход (российские домены/подсети напрямую, остальное через AUTO → DE/NL, fail-closed). **Нового туннеля RU→DE/NL строить не нужно**: он дал бы второй, неуправляемый путь мимо router (без fail-closed, AUTO и правил), потребовал бы правки WG и NAT на DE/NL и FORWARD на RU.
- Порт в INPUT придётся открыть в любом случае (VK-relay присылает пакеты на адрес сервера): это единственное изменение firewall.

## 3. Схема

До: `Клиент → Gcore CDN → RU (HAProxy → Hiddify/Xray) → xray-router → DE/NL`

После (основной вход не тронут):
```
Клиент (qWDTT) → VK TURN (relay VK) → UDP 47213 RU ─► [socat relay, хост] ─► veth 10.99.0.0/30 ─► netns "vkturn":
    qWDTT-сервер (wdtt0 10.66.0.0/16, NAT только внутри netns) → default route → xray TUN vkt0 (UDP/53 → dns, остальной UDP блокируется, TCP → SOCKS)
    → socat 127.0.0.1:1080 (в netns) ─ unix-сокет /run/vkturn/s.sock ─► socat (хост) ─► xray-router 127.0.0.1:20808 (AUTO) → DE/NL
```
Unix-сокет нужен, чтобы netns вообще не имел сетевого выхода на хост (никаких veth-маршрутов, FORWARD, NAT, DNAT на хосте). xray берётся тот, что уже стоит на RU (26.7.28); поддержку TUN-inbound на стенде я проверил на 26.3.27, а на RU её проверяет `install.sh` (`xray run -test`) до любых изменений и при отказе ничего не ставит.

## 4. Что изменяется на RU (при установке `install.sh`)

Только НОВОЕ; существующие файлы, конфиги, правила, sysctl не правятся:
- `/opt/vkturn/bin/{wdtt-server, ns-up.sh, ns-down.sh, tun-up.sh}`, `/etc/vkturn/{env, xray-ns.json, wdtt/ (пароль владельца 600, база, ключи)}`, `/run/vkturn/s.sock`
- службы `vkturn-{ns,hostbridge,xray,nsbridge,server,relay}.service` (MemoryMax 64–400 МБ, CPUQuota 100%), не заменяют существующие
- netns `vkturn`, veth `vkt-h` (10.99.0.1/30) ↔ `vkt-n` (10.99.0.2/30), TUN `vkt0`, `wdtt0` (внутри netns)
- публичный сокет: UDP 47213 (socat, слушает на хосте); закрыт firewall-ом, пока вы не откроете (`firewall-open.sh 47213`) — единственное правило, которое меняет firewall: `iptables -I INPUT -p udp --dport 47213 -j ACCEPT`. Hiddify сохраняет живые правила в rules.v4 при своём следующем применении, поэтому после теста запускайте `firewall-close.sh 47213`.
Занятые порты: UDP 47213 (хост); внутри netns: UDP 56000 (DTLS), 56001 (WG, внутренний), 56002 (direct), TCP 56000 (служебный HTTP API сервера, наружу не проброшен), TCP 1080 (127.0.0.1 в netns).
SSH, Gcore, HAProxy, панель, router, DNS, существующие systemd-службы не затрагиваются. Telegram-бот и admin API сервера qWDTT не включаются (токены не заданы).

## 5. Как запустить / проверить / удалить

Запуск (root на RU, после вашего «да»):
```
BIN=/root/vkturn/bin/wdtt-server EXPECT_SHA=$(cut -d' ' -f1 /root/vkturn/bin/wdtt-server.sha256) bash /root/vkturn/install.sh
```
Скрипт проверяет контрольную сумму бинарника, снимает слепок состояния хоста до/после (iptables, nft, ip rule, sysctl, другие службы, слушающие сокеты, маршруты) и откатывается сам, если служба не поднялась. Порт после установки ЗАКРЫТ.
Проверка: `bash check.sh` (службы, netns, слушатели, внешний IP из netns — должен быть DE/NL, DNS, ресурсы).
Тест с телефона: `bash firewall-open.sh 47213`; в qWDTT добавить сервер (IP RU, порт 47213, пароль из `/etc/vkturn/wdtt/owner.pw`) и VK-звонок-ссылку; после теста `bash firewall-close.sh 47213`.
Удаление: `bash firewall-close.sh 47213; bash uninstall.sh` — удаляет службы, файлы, netns, veth; на хосте не остаётся ничего.

## 6. Что проверено на стенде (WSL, копия RU)

- Сервер собран из исходника (Go 1.27.3 с проверенной контрольной суммой), `sha256` бинарника в `bin/wdtt-server.sha256`, коммит исходника в `bin/SOURCE_COMMIT.txt`.
- Запуск сервера в netns: до/после идентичны iptables, nft, ссылки, маршруты, sysctl (BBR, буферы, ip_forward), то есть его побочные эффекты остаются в netns.
- Пакет: установка → хост «без изменений»; пакеты от адреса клиента wdtt (10.66.x.x) выходят из netns через TUN и мост в xray-router на выходы A/B (в лабе это «иностранные» выходы); публичный UDP-порт → netns (эхо); перезапуск router — вход восстанавливается сам; SIGTERM и SIGKILL сервера — systemd поднимает; удаление — ни службы, ни netns, ни veth, ни сокета.

## 7. Что НЕ проверено (нужны вы и реальная сеть)

- Реальный VK TURN: нужны ссылка-звонок VK (хеш) и телефон; без этого handshake и скорость не измерить. Конечные точки VK (`api.vk.ru`, `calls.okcdn.ru`, `vk.com`, `id.vk.com`) с RU и с моего ПК отвечают 200/302.
- Внешний IP с телефона, DNS-утечки, скорость/RTT, смена мобильной сети, восстановление TURN-сессии, поведение при реально включённых белых списках — только с телефона.
- DNS и TCP наружу из netns на самом RU (на стенде нет интернета через лабораторные выходы): проверит `check.sh` после установки.

## 8. Ограничения и честные ответы

- **Автоматического переключения Gcore → VK TURN из Hiddify/Happ/INCY нет.** Эти клиенты не умеют запускать VK TURN. Android разрешает один VPN: qWDTT в режиме `vpn` и Hiddify вместе не работают. Это отдельный клиент и ручное переключение.
- Возможный полуавтомат (не сделан, нужна проверка на телефоне): qWDTT в режиме `socks` (не VPN, локальный SOCKS5 127.0.0.1:1080) + в Hiddify исключить qWDTT из туннеля (per-app) + в sing-box-профиле добавить outbound `socks 127.0.0.1:1080` в группу urltest/fallback рядом с Gcore. Тогда Hiddify сам уйдёт на резерв, когда Gcore недоступен, но qWDTT должен быть запущен и подключён заранее. Правка шаблона подписки Hiddify — отдельная задача.
- Через резервный вход: только TCP и DNS; прочий UDP (QUIC, звонки, игры) сознательно блокируется (мост SOCKS без UDP-relay), браузеры откатываются на TCP.
- Российские сайты (.ru, .su, .рф, geoip:ru, списки) идут напрямую с RU, как и на основном входе: иностранный IP получают нероссийские сайты. Если нужен иностранный выход для всего, берётся слот s1 (Германия) или s3 (Нидерланды) вместо 20808.
- Один общий пароль владельца; отдельные пароли пользователей делаются через admin API/бот qWDTT (не включены). Пароль теста меняется перезаписью `owner.pw` и `systemctl restart vkturn-server`.
- Правовая и сервисная сторона: схема использует инфраструктуру звонков VK (анонимный токен по ссылке-звонку); VK может изменить или ограничить это в любой момент, стабильность не гарантируется.
- qWDTT-сервер у вас один процесс на 2 vCPU; резерв рассчитан на единицы пользователей-тестеров, не на всех.
- Если безопасная установка на RU вас не устраивает: тот же пакет ставится на отдельный RU-VPS (тогда мост в router заменяется на WG-пир к DE/NL), либо сервер ставится прямо на DE: VK-relay присылает пакеты на любой адрес, зарубежный сервер даёт иностранный IP без RU-хопа (минус: правка firewall DE и мало памяти на DE).
