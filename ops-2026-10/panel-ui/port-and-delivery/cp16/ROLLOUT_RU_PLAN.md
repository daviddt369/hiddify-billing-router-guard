# CP-16: план выкладки на RU (новая оболочка V2 + дашборд + карточка нод + единая тема + русское меню)

Статус: готово и проверено ТОЛЬКО на стенде. На RU ничего не применено. Выкладка — только по явной команде владельца.

## Что меняется на RU

Новые файлы (ничего стокового не заменяется):
- `static/admin-v2/` (16 MB, 142 файла, собранный Vue-клиент с NL; `assets/index.js` с правкой первой группы меню, оригинал рядом как `index.js.orig`) + `nodes-widget.js`
- `hutils/{node_system,system_metrics,usage_cache,usage_stats}.py`
- `panel/commercial/restapi/v2/admin/{dashboard_api,dashboard_schema,nodes_status_api}.py`, `panel/commercial/restapi/v2/pydantic_schema.py`
- `panel/admin/{v2_view,v2_menu}.py`, `panel/admin/templates/admin_v2.html`
- `static/css/panel-theme.css`

Правки существующих файлов (у каждого бэкап до правки):
- `models/usage.py` — добавлен метод `get_dashboard_stats` (+ `from __future__ import annotations` первой строкой)
- `panel/commercial/restapi/v2/admin/__init__.py` — 3 маршрута (`/dashboard/`, `/dashboard/disk/`, `/nodes-status/`)
- `panel/admin/__init__.py` — вызов `register_v2_routes`
- `templates/admin-layout.html` — новый сайдбар и подключение темы (версия из CP-15 как база)

Не меняется: Xray/HAProxy/sing-box, routing, anti-share, БД, подписки, любые пользовательские данные, OS-настройки.

## Перед выкладкой (на стенде, без RU)
1. Проверить путь пакета `hiddifypanel` на RU (`.venv313/.../site-packages/hiddifypanel`, там две копии — правим только ту, что реально импортируется; владелец root, патчить от root, см. CP-11).
2. Собрать дельта-пакет `make_pkg.py` для CP-16 (формат как у CP-15, `multiloc_delta_deploy.py --new <pkg>`): новые файлы = add-new, правки = update/first-touch. Размер ~16 MB.
3. Прогнать пакет на стенде в ту же последовательность, что и на RU (dry-run без `--apply`, потом `--apply`), затем один раз профильные наборы: test_07, test_13, test_14, test_16, test_19, TestRoscomRoutingInTheJson.

## Порядок на RU
1. Бэкап: `/root/.claude-backups/cp16-<дата>/` — копия каждого затрагиваемого существующего файла + `STATE.json` (что новое, что изменено) + копия `static/admin-v2` не нужна (её на RU нет — откат = удалить).
2. `multiloc_delta_deploy.py --new <pkg>` (сухой прогон, смотрим список).
3. `--apply --backup <dir>`: инструмент сам откатывает всё при сбое, один рестарт `hiddify-panel`.
4. Проверки сразу после (ниже). Окно: не в воскресенье 23:00 МСК (перезагрузка), лучше днём, но не в пик.

## Проверки после
- `systemctl is-active hiddify-panel` = active, в журнале нет ImportError.
- Вход в админку по обычной ссылке открывается; `/admin/v2/` отдаёт оболочку; `/api/v2/admin/dashboard/`, `/dashboard/disk/`, `/nodes-status/` = 200.
- Все пункты русского меню отвечают 200 (кроме «Статистика прокси», если внешний сервис недоступен — как и раньше), активный пункт подсвечен.
- Карточка «Состояние нод»: DE и NL зелёные (сверить с реальным состоянием vpn-watch).
- Страницы: Пользователи, Домены, Протоколы, Настройки (секция раскрывается), Анти-шаринг, Локации, Внешние ноды, Happ/INCY — открываются и сохраняются; светлая/тёмная тема переключается.
- VPN-трафик не затронут: подключение с телефона, `vpn-watch` без новых алертов, xray-router/HAProxy не перезапускались.
- Подписки пользователей (Happ/INCY) отдаются как раньше.

## Откат
- Основной: `multiloc_delta_deploy.py` с бэкап-каталогом возвращает все изменённые файлы и удаляет добавленные, затем рестарт панели.
- Если инструмент недоступен: вернуть 4 изменённых файла из `cp16-<дата>/` (usage.py, restapi `__init__.py`, `panel/admin/__init__.py`, admin-layout.html), удалить новые файлы по списку из `STATE.json`, `systemctl restart hiddify-panel`.
- Только вид (если логика ок, но не нравится дизайн): убрать `<link ... panel-theme.css>` из admin-layout.html и вернуть старый сайдбар из бэкапа — остальное работает.
- Откат занимает ~1 минуту и затрагивает только панель, не VPN-трафик.

## Что известно и не блокирует
- `/api/openapi.json` отвечает 500 на RU (существующая проблема, к CP-16 не относится).
- Тексты самого дашборда (SPA) на английском — там только en/fa; перевод сделаем отдельным шагом.
- Пункты NL-меню «Utils» и «Proxy Editor» не переносились (нужен движок `proxy_v3`).
- Старые уведомления («панель устарела», предупреждение про SSH-пароль) пока как в стоке.
- Названия пунктов меню — черновик, уточним с владельцем.
