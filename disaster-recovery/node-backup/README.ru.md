# Бэкап внешних узлов (DE, NL)

Что копируется: всё, чего нет в репозитории и что нельзя пересобрать: ключи WireGuard, правила файрвола (`/etc/iptables`), настройки AdGuard и unbound, сертификаты (`/root/.acme.sh`, `ssl`), доступ по SSH, свои юниты и скрипты, база панели узла (`node-db.sql`). Не копируются: ротируемые бэкапы панели, журналы, данные MariaDB «как файлы» (вместо них дамп). Размер порядка 1-2 МБ.

## Как устроено (почему так)

```
узел  --SSH-->  ПК оператора  -->  облако (nodes/<имя>/)  <--проверка раз в час--  RU  -->  vpn-watch  -->  Telegram
```

1. **На узле** `/opt/vpn-node-backup/node-backup.sh` (запускается по SSH от root) отдаёт в stdout одним потоком архив, зашифрованный `age` на **публичный** ключ (`/opt/vpn-node-backup/age-recipient.pub`). Узел расшифровать его не может, и на узле **нет облачных ключей**: взломанный выход не сможет стереть бэкапы.
2. **На ПК** `windows-node-backup-lib.ps1` (`Invoke-NodeBackupPull`) забирает поток, проверяет (код выхода, размер, заголовок `age-encryption.org/v1`), хранит локально (последние 14) и загружает в облако `nodes/<имя>/` со сверкой размера (последние 14). Запуск: ежедневная задача Windows `VPN-DR-PullOffsiteBackup` (в 12:00 по времени ПК, с догоном, если ПК был выключен); список узлов, пользователей и ключей SSH лежит в приватном `nodes.json` (в git его нет).
3. **На RU** `nodes-backup-check.sh` (таймер раз в час) смотрит в облако и ставит отметки `/var/lib/vpn-backup/node-<имя>.ok` по времени самого свежего объекта. `vpn-watch` шлёт критическое оповещение в Telegram, если отметка старше 54 часов или её нет.

## Установка на узел

`apt-get install -y age`, затем файлы `node-backup.sh` и `age-recipient.pub` в `/opt/vpn-node-backup/` (права 700). Пробный запуск: `/opt/vpn-node-backup/node-backup.sh | wc -c` (на stderr будет журнал, на stdout только шифрованный поток).

## Восстановление узла

1. Взять архив: `E:\VPN_BACKUP\nodes-pulled\<имя>\` или из облака `nodes/<имя>/`.
2. Расшифровать приватным ключом `age` (он хранится отдельно, см. реестр бэкапов): `age -d -i ключ.txt файл.age | tar xz -C /восстановление`.
3. Свежий сервер: поставить Hiddify как дочерний узел из панели RU, затем вернуть из архива `etc/wireguard`, `etc/iptables`, настройки AdGuard/unbound и юниты; `node-db.sql` нужен, только если не хочется заново регистрировать узел.

## Тесты

`tests/test_node_backup.sh` (14 проверок: шифрование, состав, исключения, отсутствие открытого текста, чистый stdout), `tests/test_nodes_backup_check.sh` (отметки по времени объекта, часовой пояс сервера, сбой листинга ничего не меняет). Прогонялись на стенде с настоящими tar, age, mariadb-dump.
